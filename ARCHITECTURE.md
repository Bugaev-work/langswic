# Архитектура и границы совместимости

«langswic» — установочный EXE для Windows 10/11 x64 на C# 5, WinForms и системном .NET Framework 4.8, со встроенным нативным модулем смены языка. C# собирается компилятором Windows без NuGet; C — закреплённым переносимым Zig 0.14.1. Выбор даёт нативный цикл сообщений, трей, регистрацию горячих клавиш и доступ к Win32/UI Automation. Никаких сетевых API в приложении нет.

| Часть | Файлы | Ответственность |
|---|---|---|
| Системный ввод | `InputPump.cs`, `Native.cs` | Отдельный поток хуков с циклом сообщений; копирование метаданных в ограниченную очередь без чтения текста; SendInput и смена раскладки |
| Назначение языка | `LayoutService.cs`, `native/layout.c`, `native/winapi_min.h` | Кратковременный WH_CALLWNDPROC для одного потока; назначение установленного HKL в потоке приложения и подтверждение фактического языка |
| Поля ввода | `InputService.cs`, `TextAccess.cs` | Постоянный MTA-поток читает UI Automation, проверяет защищённые поля, курсор и диапазон; выполняет замену; поддерживает подтверждённые редактируемые Custom-поля |
| Определение языка | `LanguageEngine.cs`, `Native.cs` | Сопоставление физических буквенных клавиш с RU/EN, выбор при высокой уверенности и правила сохранения исходного ввода |
| Словари | `Lexicons.cs`, `WindowsSpelling.cs` | Исходные списки RU/EN, опечатки и «ё»; локальная проверка по установленным провайдерам орфографии Windows; пользовательские дополнения в JSON |
| Данные | `Settings.cs` | JSON в `%LOCALAPPDATA%\langswic\settings.json`, правила приложений, слова-исключения, локальное обучение, импорт/экспорт |
| Интерфейс | `MainForm.cs`, `VisualControls.cs`, `BrandLogo.cs`, `TrayMenuRenderer.cs`, `TaskbarIdentity.cs` | Оформленное меню трея, пять выровненных вкладок без общей прокрутки, три CheckBox-переключателя, фиксированное окно, собственный логотип, оконный ICO и AppUserModelID процесса/ярлыка, компактные категории настроек, исключений, словарей и горячих клавиш, темы |
| Запуск и пакет | `Program.cs`, `build.ps1` | Единственный экземпляр, установка на пользователя, удаление, автоматические тесты и воспроизводимая сборка |

## Путь обработки

В 1.5.2 проверка границы курсора допускает новый отслеживаемый токен перед уже существующими буквами: всё слово слева от курсора должно точно совпасть с буфером нового ввода. После навигации буфер сброшен, поэтому попытка частично преобразовать старое слово по-прежнему отвергается. Пробел между новым и старым словом также разрешает преобразование левого слова. Замена и отмена сверяют текст с обеих сторон, не выделяют всё поле и сохраняют соседние слова. После отмены без разделителя буфер соответствует восстановленному фрагменту.

Иконка окна выбирается из встроенного ICO как 32×32; у процесса и ярлыка один `Langswic.Desktop`. Установщик записывает IconLocation и System.AppUserModel.ID в .lnk, затем уведомляет оболочку об обновлении иконок. Проверка временного ярлыка подтверждает сохранённый AppID; проверка окна получает ненулевой HICON. Основания: [Microsoft AppUserModelID](https://learn.microsoft.com/en-us/windows/win32/shell/appids), [System.AppUserModel.ID](https://learn.microsoft.com/en-us/windows/win32/properties/props-system-appusermodel-id). Вид закреплённого значка в конкретном Explorer не проверялся вручную.

В 1.5.1 ручная смена языка отделена от `SafeFocus`: для Shift и пустого Double Shift используются только HWND/GUITHREADINFO/HKL, без чтения поля. При отсутствии hwndFocus получатель — активное главное окно того же потока. Нативный модуль допускает этот случай только если фокус по-прежнему отсутствует и окно остаётся активным. Преобразование слов сохраняет прежние проверки защищённого поля, выделения и поколения ввода. Команда одиночного Shift отменяется при наборе, явной навигации или смене окна; Double Shift имеет приоритет.

В 1.5.0 токен содержит цифры и клавиши EN, на которых в RU находятся буквы: скобки, кавычки, запятая, точка, тильда и их варианты Shift. `Native.Typed` явно сопоставляет эти OEM-клавиши и цифры для стандартных RU/EN, не полагаясь на состояние очереди клавиш фонового потока. Верхний регистр русских букв учитывает Shift и Caps Lock. Языковое ядро использует отдельную таблицу пар с Shift, поэтому `{` превращается в `Х`, а не остаётся перед исправленным словом.

Правило числового разделителя применяется только к целому токену вида цифры + одна `б/Б` либо `ю/Ю` + цифры, с включённой коррекцией раскладки для приложения. Контекст ссылки, почты, пути, идентификатора, исключения и неоднозначные последовательности защищены. Число исправляется без смены HKL; последующие цифры включаются в последнюю операцию отмены.

1. Хуки живут в отдельном потоке. Обработчик копирует VK/scan code, состояние клавиши, HWND и HKL в очередь максимум на 256 заданий и немедленно возвращается. Он не вызывает UI Automation, словари или чтение текста. Свой синтетический ввод пропускается; в выпускной сборке пропускается и чужой синтетический ввод. При переполнении буфер слова сбрасывается и незавершённая замена отменяется.
2. Постоянный поток MTA обрабатывает очередь последовательно. До преобразования символов проверяет процесс, раскладку, UIA `IsPassword`/`IsReadOnly` и Win32 `ES_PASSWORD`/`ES_READONLY`. Фокус нормализуется к редактируемому Edit/ComboBox/Document, включая вложенные узлы. Смена окна, поля, щелчок мышью и навигация сбрасывают слово. Из защищённого поля текст не читается. Буфер содержит текущий токен и 128 символов контекста; для проверки операции временно читается снимок доступного поля, без записи на диск.
3. После появления текста в поле таймер вызывает языковое ядро вне обработчика клавиатуры. Оно проверяет однозначный префикс либо целое слово по встроенному, пользовательскому и системному словарям. Автосмена требует неизвестного исходного слова и известного противоположного варианта. Два неизвестных варианта остаются без изменения. COM-проверка не вызывается из WH_KEYBOARD_LL; после неё повторно проверяются фокус и последовательность ввода. Системные списки не изменяются, кэш набранных слов не создаётся.
4. После разделителя утилита до 10 попыток ждёт появления слова в поле. Новый ввод или смена фокуса отменяют ожидание. В Win32 Edit используется `EM_REPLACESEL`. В UIA-полях снимок TextPattern определяет численные границы диапазона; текст до него, выделение и текст после него должны точно совпасть с полным текстом поля. Снимок может быть до 64 Ки символов, замена — до 4096 символов. Проверяется фактическое выбранное слово до ввода и полное содержимое с курсором после ввода. Замены всего поля через Ctrl+A и непроверенных Backspace в коде нет.
5. В версии 1.4.1 путь замены слова у курсора не вызывает `TextPatternRange.Select()` и не выделяет слово через Shift+Left. Дважды сверяются полный текст, исходное выделение, положение курсора, фокус и поколение ввода. Затем один вызов SendInput отправляет Backspace строго по длине подтверждённого слова и вставку Unicode. Физические события не могут вклиниться внутрь этой очереди; между перемещением курсора и вставкой нет отдельного ожидания. Переводы строк, табуляция и сложные графемы в таком диапазоне пропускаются. Уже выделенный пользователем текст заменяется прямой вставкой после повторной проверки. Результат проверяется по полному тексту и курсору. Это предотвращает перенос курсора в начало документа провайдером с неисправным Select. Данные не берутся из ValuePattern как доказательство положения курсора. Double Shift измеряется по времени исходных клавиатурных событий. Удерживаемые модификаторы и новый ввод отменяют ожидающую ручную замену. Сохраняется одна операция для отмены; выученные правила и их запись передаются обратно в поток интерфейса, чтобы не редактировать JSON одновременно с настройками. Буфер обмена не используется.

Раскладка читается у потока HWND фокуса, который может отличаться от потока главного окна. Целевой язык выбирается по исправленному тексту. В 1.4.2 нативный DLL устанавливается через WH_CALLWNDPROC только в этот поток на время одного зарегистрированного сообщения (ожидание до 100 мс). Модуль проверяет активное окно, HWND фокуса, принадлежность потоку и наличие HKL среди уже установленных раскладок; затем вызывает ActivateKeyboardLayout в самом потоке приложения. Он не читает и не хранит текст, не обрабатывает клавиши, не пишет файлы и не использует сеть. Хук снимается в finally. DLL имеет исходники C и явные определения Win32 ABI x64, без C runtime; ресурс проверяется по SHA-256 перед загрузкой. При недоступности нативного пути используется обычный WM_INPUTLANGCHANGEREQUEST.

Проверяется фактический HKL; допускается до трёх повторных попыток с интервалом 40 мс. Обычный буквенный ввод их не отменяет. Смена фокуса, щелчок, навигация, Ctrl/Alt/Win и смена языка на сторонний HKL прекращают ожидание. Отказ отражается в диагностике. Поддержка нативного пути ограничена обычными процессами x64 текущего пользователя: процессы x86, повышенные и защищённые приложения могут отклонить обычный запасной запрос. Отмена возвращает язык исходного текста; смешанному выделению единый язык не назначается. Ранняя коррекция обновляет буфер и раскладку сразу после отправки вставки. Остаток слова, пришедший ещё в исходной раскладке, сверяется и исправляется, в том числе после разделителя. Регрессия проверяет последующие сырые клавиши, которые не исправляются словарём, при полном отказе обоих тестовых HWND от обычных запросов.

Основания: [ActivateKeyboardLayout](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-activatekeyboardlayout) действует в вызывающем потоке/процессе; [SetWindowsHookEx](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowshookexw) допускает DLL-хук в заданном потоке соответствующей разрядности. Только публикации WM_INPUTLANGCHANGEREQUEST недостаточно: приложение вправе его отклонить.

## Границы Windows API

Низкоуровневый хук и `SendInput` работают в интерактивном сеансе пользователя. Windows может ограничить ввод в приложения с более высоким уровнем целостности. Некоторые поля не сообщают тип и признак пароля через UI Automation; такие поля пропускаются. `SendInput` не предоставляет транзакционное редактирование богатого текста, поэтому смешанное форматирование и выделение в Word или веб-редакторах гарантировать нельзя. В обычных Edit-полях выделение остаётся выбранным; в веб-редакторе после замены курсор остаётся в конце вставленного текста, чтобы следующий ввод не удалил его. Поля с несколькими курсорами, IME-композиция, виртуальные клавиатуры, терминалы, игры с Raw Input и удалённые сеансы не являются поддерживаемыми целями автоматики.

Поведение хука основано на [SetWindowsHookEx](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowshookexw), [LowLevelKeyboardProc](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelkeyboardproc), [KBDLLHOOKSTRUCT](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-kbdllhookstruct), [UI Automation](https://learn.microsoft.com/en-us/windows/win32/api/uiautomationclient/nn-uiautomationclient-iuiautomationelement) и [RegisterHotKey](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey).

Разделение потоков соответствует рекомендациям Microsoft: [быстрый обработчик на отдельном потоке](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelkeyboardproc) и [UI Automation на потоке MTA без окон](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-threading). Задержка UIA больше секунды не задерживает обработчик клавиатуры: это отдельно проверено тестом с задержкой 1600 мс.

Системная проверка использует [ISpellCheckerFactory](https://learn.microsoft.com/en-us/windows/win32/api/spellcheck/nn-spellcheck-ispellcheckerfactory) и [ISpellChecker.Check](https://learn.microsoft.com/en-us/windows/win32/api/spellcheck/nf-spellcheck-ispellchecker-check). Поддержка языка зависит от установленного языкового компонента Windows. Отсутствие провайдера не мешает запуску: остаются встроенные и пользовательские словари. Интерфейсы COM сверены с официальным заголовком Microsoft win32metadata; подключение не требует NuGet.

Невозможно доказать отсутствие ошибок во всех приложениях на основании проверки одного Windows-компьютера. Поэтому по умолчанию исключены популярные IDE, терминалы и `mstsc`; остальные проблемные процессы добавляются на экране «Исключения».
