# Архитектура и границы совместимости

«Fast Switcher» — однофайловый EXE для Windows 10/11 x64 на C# 5, WinForms и системном .NET Framework 4.8. Сборка использует компилятор Windows без NuGet. Выбор даёт нативный цикл сообщений, трей, регистрацию горячих клавиш и доступ к Win32/UI Automation в одной фоновой программе. Никаких сетевых API в приложении нет.

| Часть | Файлы | Ответственность |
|---|---|---|
| Системный ввод | `InputPump.cs`, `Native.cs` | Отдельный поток хуков с циклом сообщений; копирование метаданных в ограниченную очередь без чтения текста; SendInput и смена раскладки |
| Поля ввода | `InputService.cs`, `TextAccess.cs` | Постоянный MTA-поток читает UI Automation, проверяет защищённые поля, курсор и диапазон; выполняет замену; поддерживает подтверждённые редактируемые Custom-поля |
| Определение языка | `LanguageEngine.cs`, `Native.cs` | Сопоставление физических буквенных клавиш с RU/EN, выбор при высокой уверенности и правила сохранения исходного ввода |
| Словари | `Lexicons.cs`, `WindowsSpelling.cs` | Исходные списки RU/EN, опечатки и «ё»; локальная проверка по установленным провайдерам орфографии Windows; пользовательские дополнения в JSON |
| Данные | `Settings.cs` | JSON в `%LOCALAPPDATA%\FastSwitcher\settings.json`, правила приложений, слова-исключения, локальное обучение, импорт/экспорт |
| Интерфейс | `MainForm.cs` | Трей, страницы настроек, исключений, словарей, горячих клавиш и диагностики, темы |
| Запуск и пакет | `Program.cs`, `build.ps1` | Единственный экземпляр, установка на пользователя, удаление, автоматические тесты и воспроизводимая сборка |

## Путь обработки

1. Хуки живут в отдельном потоке. Обработчик копирует VK/scan code, состояние клавиши, HWND и HKL в очередь максимум на 256 заданий и немедленно возвращается. Он не вызывает UI Automation, словари или чтение текста. Свой синтетический ввод пропускается; в выпускной сборке пропускается и чужой синтетический ввод. При переполнении буфер слова сбрасывается и незавершённая замена отменяется.
2. Постоянный поток MTA обрабатывает очередь последовательно. До преобразования символов проверяет процесс, раскладку, UIA `IsPassword`/`IsReadOnly` и Win32 `ES_PASSWORD`/`ES_READONLY`. Фокус нормализуется к редактируемому Edit/ComboBox/Document, включая вложенные узлы. Смена окна, поля, щелчок мышью и навигация сбрасывают слово. Из защищённого поля текст не читается. Буфер содержит текущий токен и 128 символов контекста; для проверки операции временно читается снимок доступного поля, без записи на диск.
3. После появления текста в поле таймер вызывает языковое ядро вне обработчика клавиатуры. Оно проверяет однозначный префикс либо целое слово по встроенному, пользовательскому и системному словарям. Автосмена требует неизвестного исходного слова и известного противоположного варианта. Два неизвестных варианта остаются без изменения. COM-проверка не вызывается из WH_KEYBOARD_LL; после неё повторно проверяются фокус и последовательность ввода. Системные списки не изменяются, кэш набранных слов не создаётся.
4. После разделителя утилита до 10 попыток ждёт появления слова в поле. Новый ввод или смена фокуса отменяют ожидание. В Win32 Edit используется `EM_REPLACESEL`. В UIA-полях снимок TextPattern определяет численные границы диапазона; текст до него, выделение и текст после него должны точно совпасть с полным текстом поля. Снимок может быть до 64 Ки символов, замена — до 4096 символов. Проверяется фактическое выбранное слово до ввода и полное содержимое с курсором после ввода. Замены всего поля через Ctrl+A и непроверенных Backspace в коде нет.
5. Если TextPattern.Select не устанавливает нужное выделение, программа восстанавливает исходный курсор, сверяет его и пробует выделение Shift+Left; вставка допускается только после проверки точного диапазона. Данные не берутся из ValuePattern как доказательство положения курсора. Double Shift измеряется по времени исходных клавиатурных событий. Удерживаемые модификаторы и новый ввод отменяют ожидающую ручную замену. Сохраняется одна операция для отмены; выученные правила и их запись передаются обратно в поток интерфейса, чтобы не редактировать JSON одновременно с настройками. Буфер обмена не используется.

Раскладка читается у потока HWND фокуса, который может отличаться от потока главного окна. Запрос изменения отправляется полю с ограничением ожидания 150 мс, затем при тайм-ауте — главному окну. Ранняя коррекция обновляет буфер и раскладку сразу после отправки вставки, до ожидания её подтверждения. Новый пользовательский ввод после уже отправленной вставки не превращает её в неудавшуюся операцию. Если остаток раннего слова пришёл ещё в исходной раскладке, он сверяется и исправляется целиком, в том числе после разделителя. Сценарий продолжения ввода при задержке подтверждения 500 мс и последующей полной отмены пройден.

## Границы Windows API

Низкоуровневый хук и `SendInput` работают в интерактивном сеансе пользователя. Windows может ограничить ввод в приложения с более высоким уровнем целостности. Некоторые поля не сообщают тип и признак пароля через UI Automation; такие поля пропускаются. `SendInput` не предоставляет транзакционное редактирование богатого текста, поэтому смешанное форматирование и выделение в Word или веб-редакторах гарантировать нельзя. В обычных Edit-полях выделение остаётся выбранным; в веб-редакторе после замены курсор остаётся в конце вставленного текста, чтобы следующий ввод не удалил его. Поля с несколькими курсорами, IME-композиция, виртуальные клавиатуры, терминалы, игры с Raw Input и удалённые сеансы не являются поддерживаемыми целями автоматики.

Поведение хука основано на [SetWindowsHookEx](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowshookexw), [LowLevelKeyboardProc](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelkeyboardproc), [KBDLLHOOKSTRUCT](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-kbdllhookstruct), [UI Automation](https://learn.microsoft.com/en-us/windows/win32/api/uiautomationclient/nn-uiautomationclient-iuiautomationelement) и [RegisterHotKey](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey).

Разделение потоков соответствует рекомендациям Microsoft: [быстрый обработчик на отдельном потоке](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelkeyboardproc) и [UI Automation на потоке MTA без окон](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-threading). Задержка UIA больше секунды не задерживает обработчик клавиатуры: это отдельно проверено тестом с задержкой 1600 мс.

Системная проверка использует [ISpellCheckerFactory](https://learn.microsoft.com/en-us/windows/win32/api/spellcheck/nn-spellcheck-ispellcheckerfactory) и [ISpellChecker.Check](https://learn.microsoft.com/en-us/windows/win32/api/spellcheck/nf-spellcheck-ispellchecker-check). Поддержка языка зависит от установленного языкового компонента Windows. Отсутствие провайдера не мешает запуску: остаются встроенные и пользовательские словари. Интерфейсы COM сверены с официальным заголовком Microsoft win32metadata; подключение не требует NuGet.

Невозможно доказать отсутствие ошибок во всех приложениях на основании проверки одного Windows-компьютера. Поэтому по умолчанию исключены популярные IDE, терминалы и `mstsc`; остальные проблемные процессы добавляются на экране «Исключения».
